A native-audio agent and a cascaded agent can both sound convincing in a short demonstration. The important differences appear when you need to inspect a mistake, change a component or constrain an external action.

Compare **the interfaces you can observe and control**, then evaluate both designs on the same conversations. Architecture alone does not establish accuracy, safety, price or conversational quality.

## Pipeline Choices

A cascade exposes STT text, language-model output and TTS input as separate boundaries. Native speech-to-speech accepts audio and generates audio within an integrated model interface. Hybrid systems combine parts of both.

<LearnDiagram name="s2s" caption="Both architectures still need application-side control of business actions. Transcript availability and audio behaviour depend on the model interface." />

| Design | Useful control | Check before choosing |
| --- | --- | --- |
| Cascade | Inspect and replace separate recognition, reasoning and synthesis stages | Integration delay, text transformations and interruption behaviour |
| Native audio | Give the model access to information carried in the audio | Exposed events, tool support, transcript semantics and output control |
| Hybrid | Add selected checkpoints or external components | Whether the extra path changes timing or introduces disagreement |

## Audio Context

Audio contains timing, speaker overlap and prosody that a plain transcript does not fully represent. An audio-native model can use those signals, but capability is model-specific.

Speech-to-speech does not automatically mean full duplex. The [Moshi paper](https://arxiv.org/abs/2410.00037) describes a particular speech-text architecture with parallel audio streams for full-duplex conversation. Other APIs expose different turn-taking behaviour. Test simultaneous speech, acknowledgements and interruptions instead of inferring support from a product label.

## Transcript Limits

A cascade provides useful text checkpoints. Its STT text can still be wrong, and its generated answer may differ from what the caller heard because synthesis, cancellation or playback changed the output.

Native-audio systems may expose input or output transcriptions; their meaning must be checked against the interface. For example, [Gemini Live documents audio transcription](https://ai.google.dev/gemini-api/docs/live-api/capabilities) alongside its audio features. Do not assume every transcript is an exact internal representation, or that every model has only an after-the-fact transcript.

For an investigation, retain the relevant audio, transcript events, configuration and tool records under your retention policy. Neither architecture’s text alone proves what reached a caller. Requirements for a formal record should be established separately from model selection.

## Tool Boundaries

Both designs need a trusted application boundary before consequential actions. Validate identities, fields, permissions and business state. Use targeted clarification for ambiguous inputs and handle uncertain tool outcomes explicitly.

Keep that boundary independent of the model provider where practical. This makes comparisons and migrations easier. The [language-model guide](/learn/components/language-model-for-voice#tool-boundaries) describes the proposal, validation and result loop.

## Operating Costs

Compare the same completed workload, including audio input and output, text or cached context, retries, tools and infrastructure. A per-token price is not a per-successful-call price.

Record costs with the quality and latency outcomes. A cheaper attempt can become more expensive if callers repeat themselves or the workflow needs recovery. There is no architecture-wide price winner; use the provider’s current billing units and your measured traffic.

## Evaluation Plan

| Scenario | Evidence to compare |
| --- | --- |
| Ambiguous identifier | Clarification and final action correctness |
| Overlapping speech | Missed words, false stops and recovery |
| Tool failure | Accurate reporting of the operation’s state |
| Long conversation | Context retention, response delay and cost |
| Provider outage | Recovery path and retained conversation state |

Hold the tasks, tools and audio conditions constant. Choose the design that meets the operational requirements with the least complexity your team can maintain. Use the [STT](/learn/components/speech-to-text), [TTS](/learn/components/text-to-speech) and [turn-detection](/learn/components/turn-detection) guides to diagnose which boundary failed.
