A batch needs rectangular tensors, but utterances have different frame counts. The solution is to pad the feature sequences and carry their true lengths through every stage that changes time resolution.

## Batch Shapes

```python
x = pad_sequence([r['x'] for r in examples], batch_first=True)
input_lengths = torch.tensor([len(r['x']) for r in examples])
y = torch.cat([r['y'] for r in examples])
target_lengths = torch.tensor([len(r['y']) for r in examples])
```

The lab packs targets end to end. The target-length vector tells the loss how to divide that stream back into examples. Padding targets with blank symbols would change the target sequence rather than merely filling space.

## Length Accounting

Our two stride-two convolutions each produce `ceil(length / 2)` frames. The code computes this using integer arithmetic:

```python
output_lengths = ((input_lengths + 1) // 2 + 1) // 2
```

Those are the lengths passed to CTC. The bidirectional GRU uses packed sequences so its backward pass does not treat padded frames as later audio. The convolution still has its declared boundary padding; the mask does not remove that architectural choice.

[PyTorch's CTC interface](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CTCLoss.html) specifies the log-probability and length inputs. Keep a tiny batch where you can inspect all dimensions before running the full experiment.

## Invalid Alignments

A target with adjacent repeated symbols needs separator frames under CTC. For example, `77` cannot be represented by only two consecutive frames labelled seven: they collapse to one. More aggressive time downsampling can make some targets impossible.
