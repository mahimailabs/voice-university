A partial transcript is a hypothesis produced before all the evidence is available. Earlier characters can change when later audio arrives. The replay below uses saved outputs from our offline model applied to growing audio prefixes.

## Replay Evidence

<STTLab mode="partials" client:load />

Each step adds up to 200 milliseconds of source audio. The last step uses the remaining samples. These are audio-prefix timestamps, not measured network arrival or response times. The model recomputes each prefix from scratch.

## Revision Handling

A consumer should know whether an update replaces an earlier hypothesis or appends new text. Blindly concatenating partial strings can duplicate tokens. Keep an utterance or segment identity, update sequence and explicit commitment state.

[Google's streaming result schema](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/StreamingRecognitionResult) distinguishes interim stability from finality. That API's fields are not calibrated confidence values for this homemade model; do not copy the names and imply equivalent semantics.

## Measure Revisions

For each prefix, retain its audio boundary and hypothesis. Count changed suffixes or edit distance between consecutive hypotheses using a declared definition. A stable wrong output is still wrong, so report final recognition accuracy separately.
