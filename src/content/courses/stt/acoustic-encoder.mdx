The model has three jobs: reduce the frame rate, combine acoustic context and assign a probability to each token. Every weight in these stages starts randomly. There is no pretrained speech encoder hidden in the baseline.

## Model Stages

<LearnDiagram name="stt-model" caption="Offline baseline: spectral frames pass through strided convolutions, a bidirectional GRU and an eleven-token output head." />

```python
self.conv = nn.Sequential(
    nn.Conv1d(129, 64, 5, stride=2, padding=2), nn.ReLU(),
    nn.Conv1d(64, 64, 5, stride=2, padding=2), nn.ReLU())
self.gru = nn.GRU(64, 64, batch_first=True, bidirectional=True)
self.head = nn.Linear(128, 11)
```

The two GRU directions produce 128 features per frame. The final linear layer maps those features to eleven scores, and `log_softmax` turns them into the log probabilities consumed by the loss.

## Context Cost

The backward GRU direction uses later frames. This makes the baseline an offline encoder even if the forward pass is very fast. Feeding it partial audio repeatedly can produce useful previews, but that is not equivalent to incremental inference with a causal model.

Packing lengths matters here: padded frames should not become future context. Revisit [Batch Construction](/learn/100x/stt/batch-construction) before replacing the recurrent layer.
